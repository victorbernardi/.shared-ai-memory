Nossos testes físicos provaram que isso é impossível.*\n* **As Provas Técnicas Coletadas:**\n  1. **A Barreira do SSO Okta:** A John Deere não disponibiliza chaves de API estáticas de longa duração. A única forma de autenticar nas APIs de exportação do portal é por meio do token de sessão JWT gerado após o fluxo interativo do Okta SSO com 2FA. Sem o navegador físico e o SMS do usuário, a conexão é bloqueada na origem.\n  2. **Fragilidade de Código:** Tentar interceptar o token de sessão JWT programaticamente para fazer chamadas HTTP de API em segundo plano (`requests.post`) gera código altamente complexo e instável. Mudanças na criptografia do Okta ou na segurança da Deere quebram a extração de forma silenciosa.\n  3. **Timeouts por Volume:** A chamada brute-force da API de exportação com múltiplos filtros gigantes ou requisições em paralelo gera instabilidade, resultando em erros `HTTP 504 Gateway Timeout` ou `HTTP 502 Bad Gateway` por parte do servidor remoto da Deere.\n* **Callout:** *\"Nenhum servidor consegue automatizar a API direta de frotas sem passar pela interface visível e a validação do 2FA corporativo.\"*\n\n---\n\n### Slide 6: Cenário 3 — A Solução: Automação Híbrida Standalone
