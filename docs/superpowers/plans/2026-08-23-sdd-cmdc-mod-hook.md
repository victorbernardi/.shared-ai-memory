# SDD Command Code Mod Hook Preflight Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make the Windows Mod-hook preflight diagnose `MOD_HOOK_UNVERIFIED` with bounded, actionable evidence while ensuring every Command Code invocation enters `--yolo` mode, including normal workers, recovery, resume, and legacy compatibility routes.

**Architecture:** Keep the dedicated `_mod_probe.ts` as the only preflight capability probe. The shared `CmdcLocal` command builder and the legacy compatibility builder always append `--yolo`, so the worker, recovery, resume, and smoke paths cannot silently fall back to normal permission mode. The Run Contract keeps its existing `execution.yolo` field for schema compatibility, but normalization writes `true` and loading rejects `false`; the immutable policy therefore records the same mode that the launcher enforces. When the exact protocol handshake is absent, `CmdcLocal` will render bounded evidence from the completed smoke outcome and a remediation path through the existing `CmdcLocalError`/lifecycle blocker boundary.

**Tech Stack:** Python 3.12, pytest, TypeScript Command Code Mod probe, Windows `cmdc.cmd`/`cmdc.ps1` launcher wrappers.

## Global Constraints

- The preflight remains fail-closed: absence of the exact `tool_hook_blocked` event with `hookOutput=SDD_CMDC_MOD_HOOK_HANDSHAKE` must block the Run; it must never fall back to Codex or treat marker text as proof.
- The diagnostic must preserve the stable `BLOCKER_CODE: MOD_HOOK_UNVERIFIED` and the existing `smoke did not emit SDD_CMDC_MOD_HOOK_OK` text while adding bounded session/process/event evidence and a concrete launcher/Mod remediation path.
- Every Command Code child process must receive `--yolo`. The legacy `--allow-cmdc-yolo` option remains accepted only for caller compatibility and is no longer a gate; diagnostics and the immutable Contract must report `yolo` consistently.
- On the Windows CMDc launcher, issue file reads and writes sequentially; do not emit parallel `read_file`, `write_file`, or edit tool calls in one turn, because the observed launcher closed its protocol pipe with `write EOF` before a terminal result.
- Do not expose prompts, secrets, full NDJSON streams, or unbounded paths in the diagnostic; cap event-type evidence and include only the launcher/protocol fields needed to remediate the boundary.
- Deterministic fake-launcher tests and the installed-launcher smoke remain separate; a skipped real smoke is unavailable operational evidence, not success.
- Python bytecode/cache files generated by importing the adapter must not make the canonical skill checkout dirty before preflight captures its baseline.
- Do not change the fixed implementation model, Run Contract schema shape, scope gates, or review backend routing. The existing `execution.yolo` boolean remains part of the schema, with `true` as the only valid value.
