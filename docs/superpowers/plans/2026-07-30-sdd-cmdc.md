# sdd-cmdc Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Criar, validar, registrar e disponibilizar a skill `sdd-cmdc`, preservando o fluxo de `subagent-driven-development` e substituindo somente os implementadores por `cmdc` com `deepseek/deepseek-v4-flash`.

**Architecture:** Uma cópia independente de `skills/subagent-driven-development` conterá o fluxo SDD e um adaptador Python determinístico. O adaptador executará `cmdc` em modo de edição, validará o resultado e emitirá diagnósticos estruturados; os reviewers continuarão sendo despachados pelo Codex. A fonte canônica será `C:\Users\victor.bernardi\.shared-ai-memory\skills`; os destinos físicos de runtime serão sincronizados somente depois da validação da nova skill.

**Tech Stack:** Markdown/YAML de Agent Skills, Python 3, `pytest`, Command Code CLI 1.5.0, PowerShell/Windows e Git.

## Global Constraints

- O implementador roda por `cmdc`, em modo de edição, com o modelo fixo `deepseek/deepseek-v4-flash`.
- No Windows, `cmdc` é o executável preferencial para evitar a colisão de `cmd` com `C:\Windows\System32\cmd.exe`.
- Reviewers, re-reviewers e reviewer final permanecem Codex e preservam a ordem original.
- Falhas do adaptador não serão convertidas em `DONE` nem em implementação Codex.
- O formato de bloqueio inclui `STATUS`, `BLOCKER_CODE`, `MESSAGE`, `COMMAND`, `EXIT_CODE`, `STDERR` e `ACTION`.
- Os códigos de bloqueio são `CMD_NOT_FOUND`, `AUTH_REQUIRED`, `MODEL_UNAVAILABLE`, `RATE_LIMITED`, `TIMEOUT`, `PROCESS_FAILED` e `REPORT_MISSING`.
- O padrão de `--max-turns` é `20`; ele pode ser ajustado por tarefa sem alterar o modelo obrigatório.
- Não modificar `skills/subagent-driven-development` nem arquivos não relacionados.
- Preservar alterações locais existentes e não executar merge, push ou reset destrutivo.
- Cada tarefa que modifica arquivos rastreados deve terminar com testes executados e um commit próprio; tarefas de validação de destinos externos devem registrar o resultado sem criar commit artificial.
