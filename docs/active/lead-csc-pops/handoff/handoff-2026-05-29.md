## O Que Foi Feito Nesta Sessão

### 1. Separação write path / read path (Power Query desacoplamento)

- `run.py` agora escreve em `leads-csc-pops-base.xlsx` (`--output`)

- Novo argumento `--producao` aponta para o arquivo de produção (fonte de feedback de retorno/observações)

### 2. Fix crítico: Horimetro_Base = 0 no bootstrap

- **Bug:** O bloco `primeiro_processamento` só atualizava `base = h_atual` para chassis *sem* alerta; chassis alertados ficavam com `base = 0` salvo no estado → disparavam em todo ciclo de produção
- **Fix:** `df_ativos['Horimetro_Base'] = df_ativos['Work Order Hours Reported']` aplicado a *todos* os chassis, sem condicional
- **Impacto corrigido:** 448 chassis indevidos (404 FPS + 43 Tratores + 1 Escavadeira com `base=0` e `h % threshold > tolerance`)

### 3. Coluna "Primeiro Alerta" (col K)

- Rastreamento via `data/state/alertas_ocorrencias.parquet` (`Serial Number` + `Data_Primeiro_Alerta`)
- "Sim" = verde (#367C2B) | "Não" = cinza (#AAAAAA)
- Planilha agora tem **16 colunas** (era 15)

### 4. Renomeação Delta Horas → Delta Horímetro

- Correção conceitual: a diferença é entre leituras de horímetro (horas de operação), não horas de calendário
- Leitura backward-compatible: `row_tr.get('Delta Horimetro', row_tr.get('Delta Horas', 0.0))`

### 5. Script de auditoria consolidado

- `scripts/diagnostico_estado_pipeline.py` — substitui os scripts ad-hoc de auditoria
- Audita `horimetro_base_estado.parquet`: chassis com `base=0`, standby indevidos, distribuição de delta
- Reutilizável para qualquer projeto com a mesma arquitetura de horímetro

| Família | Threshold | Range Bootstrap |
|---------|-----------|-----------------|
| CARREGADEIRAS | 200h | 50h |
| TRATORES DE ESTEIRA | 1500h | 500h |
| ESCAVADEIRAS | 3000h | 1000h |

**Regra standby:** `h % threshold > range_boot` → máquina JÁ passou do trigger mas não está no range do próximo → fica em standby até atingir o próximo múltiplo.
