## 5 bugs reais detectados

### Bug 1 — Sessão errada salva (severidade: ALTA)

**Sintoma:** Rodar `python antigravity/skills/context-agent/scripts/context_manager.py save` de dentro de uma sessão Claude Code salvou conteúdo de outra sessão (Inova/John Deere) que rodava no Antigravity em paralelo.

**Causa raiz:** O save Antigravity lê o `overview.txt` mais recente do brain `~/.gemini/antigravity/brain/`. Não tem como saber qual sessão é a "atual" do motor que invocou o save — sempre pega a mtime mais recente, que pode ser de qualquer projeto.

**Implicação arquitetural:** Cada motor precisa salvar a *sua própria* sessão. Para esta sessão Claude Code, o save correto seria via `~/.claude/skills/context-agent/scripts/context_manager.py` lendo `.jsonl` do próprio Claude Code.

**Não é bug do parser — é arquitetural.** O Stop hook (T8) é a solução: ele dispara *no fim da sessão Claude Code* e tem acesso ao `transcript_path` correto via stdin do hook.

**Fix proposto:**
- Adaptar `context_manager.py save` para aceitar `--transcript-path <path>` (já está documentado em `2026-04-28-fase1-correcoes.md` linha 678).
- Stop hook em `settings.json` passa `transcript_path` recebido via stdin ao script.
- Sem `--transcript-path`, cair no comportamento atual (mtime mais recente) com warning explícito.

### Bug 2 — `CLAUDE_SESSION_DIR` hardcoded sem env var (severidade: ALTA)

**Sintoma:** Esta sessão está gravada em `C--Users-victor-bernardi--claude/bd3a97c1-…jsonl` (2.8 MB, Apr 29 08:20). Mas o parser pegou `C--Projetos-Stout/235ca7ca-…jsonl` (85 KB, Apr 28 — sessão antiga de outro contexto).

**Causa raiz:** Em `~/.claude/skills/context-agent/scripts/config.py`:
```python
AGENT_ROOT = USER_PROFILE / ".claude"
CLAUDE_SESSION_DIR = AGENT_ROOT / "projects" / "C--Projetos-Stout"  # hardcoded
```

Não usa `_env_path("CLAUDE_SESSION_DIR", default)` como o resto. O encoded path do Claude Code muda por sessão (depende de onde o CLI foi lançado, não só do cwd).

**Fix proposto:**
```python
CLAUDE_SESSION_DIR = _env_path(
    "CLAUDE_SESSION_DIR",
    AGENT_ROOT / "projects" / "C--Projetos-Stout",
)
```

E no Stop hook, exportar `CLAUDE_SESSION_DIR` para o subdir correto (ou ainda melhor — passar `--transcript-path` direto, ver Bug 1).

### Bug 3 — `get_next_session_number()` regressivo (severidade: MÉDIA)

**Sintoma:** Título do arquivo gerado: `# Sessão 20260430 — 2026-04-29`. O número 20260430 é amanhã.

**Causa raiz:** Em `session_summary.py`:
```python
num = int(f.stem.split("-")[1])
```

Para arquivos novos `session-20260429-014526-antigravity-XX.md`, `[1]` é `20260429` (data como int). `max + 1` vira `20260430`. Função era para o formato legado `session-001.md` e ficou contaminando o título com timestamp + 1.

**Fix proposto:** Após T8.6 (timestamp+UUID), o `session_number` perdeu sentido. Remover a chamada a `get_next_session_number()` e o campo `summary.session_number` — usar timestamp ISO no título:
```python
lines = [
    f"# Sessão {summary.date} — {SESSION_ORIGIN}",
    ...
]
```

Ou manter `session_number` como string `summary.timestamp` (`20260429-014526`) para coerência com o filename.

### Bug 4 — Extractor de tópicos pega marcadores literais (severidade: MÉDIA)

**Sintoma:** Tópicos extraídos: `<USER_REQUEST>` e `Comments on artifact URI: file:///c%3A/Users/victor`.

**Causa raiz:** O `overview.txt` do Antigravity envolve a primeira mensagem do usuário em `<USER_REQUEST>...</USER_REQUEST>`. Outros entries têm artifact metadata. O extractor de tópicos não filtra tags/metadata estruturais.

**Fix proposto:** No `_extract_topics()` (ou equivalente), antes de calcular tópicos:
- Strip de tags `<USER_REQUEST>`, `</USER_REQUEST>`, `<ADDITIONAL_METADATA>`, `</ADDITIONAL_METADATA>`
- Pular linhas que começam com `Comments on artifact URI:` ou regex `^[A-Z][a-z]+ on \w+ URI:`
- Pular linhas com 100% URI / file path

### Bug 5 — Link "Sessão anterior" quebrado (severidade: BAIXA)

**Sintoma:** Footer do arquivo: `*Sessão anterior: [session-20260429](session-20260429.md)*`. Esse arquivo não existe.

**Causa raiz:** Cálculo do nome do arquivo anterior usa `summary.session_number - 1` com formato legado `session-NNN.md`.

**Fix proposto:** Após Bug 3, descontinuar `session_number`. Footer deve linkar para o `session-*.md` mais recente *anterior* a este (ordenar por mtime, pegar penúltimo):
```python
sessions = sorted(SESSIONS_DIR.glob("session-*.md"), key=lambda p: p.stat().st_mtime, reverse=True)
prev = next((s for s in sessions if s != current_path), None)
```
