## Objetivo

Evoluir o `scanner_performance_360.py` de um motor de consulta de vendas para uma **ferramenta de diagnóstico completa**, integrando o Eixo Estoque (parquet local) ao Eixo Vendas (Fabric) em uma única saída tabular.

---

## Contexto Técnico (Mapeamento de Dados)

### Colunas disponíveis no Parquet (`base_estoque_enriquecida.parquet`)
As colunas relevantes para o Eixo Estoque já existem no parquet:

| Coluna | Uso no Scanner |
|--------|---------------|
| `ITEM` | Chave de JOIN com os dados de vendas |
| `SUBGRUPO_FULL` | Campo para busca/agrupamento por subgrupo |
| `GRUPO` | Campo para busca/agrupamento por grupo |
| `DESCRICAO` | Descrição do item |
| `ESTOQUE CONTÁBIL` | Saldo atual em unidades |
| `VALOR DE INV CONTÁBIL` | Valor total do inventário (R$) |
| `ESTOQUE EXCEDENTE` | Excesso em unidades |
| `VALOR DE INV EXCEDENTE` | Capital parado em R$ |
| `POPULARIDADE` | HIGH / MEDIUM / LOW |
| `CLASSIFICACAO DETALHADA` | Status: ex: "Zero Vendas 12m", "Excesso 24m" |
| `VENDAS_ANO_1`, `_ANO_2`, `_ANO_3` | Tendência calculada (já pronta) |

> **Observação:** O parquet contém 40.104 linhas (nível de ITEM x CONTA). Para o Scanner,
> será necessário agregar por `ITEM` antes do JOIN.

## Plano de Tarefas

### Task 1 — Refatoração: Separar a query em função reutilizável

**Arquivo:** `scripts/scanner_performance_360.py`

O código atual tem a query e a exibição misturadas. Vamos separar para facilitar a integração:

```python
# ANTES (atual): tudo numa função
def run_performance_check(target_type, target_value): ...

# DEPOIS: duas funções separadas
def _fetch_sales_data(motor, filter_sql) -> pd.DataFrame: ...  # só a query
def _display_sales_analysis(df) -> None: ...                   # só a exibição
def _fetch_stock_data(target_type, target_value) -> pd.DataFrame | None: ...  # eixo estoque
def _display_stock_analysis(df) -> None: ...                   # exibição do estoque
def run_performance_check(target_type, target_value): ...       # orquestrador
```

---

### Task 2 — Implementar: `_fetch_stock_data()`

**Lógica:**
1. Verificar existência de `data/base_estoque_enriquecida.parquet`
2. Se não existir: imprimir aviso e retornar `None`
3. Se existir: exibir data de atualização do arquivo
4. Se arquivo tiver mais de 7 dias: exibir AVISO de dado desatualizado
5. Carregar parquet
6. Agregar por ITEM (soma de estoque, excesso, valor)
7. Aplicar filtro pelo `target_type`:
   - `item`: filtrar `ITEM LIKE '%valor%'`
   - `subgrupo`: filtrar `SUBGRUPO_FULL LIKE '%valor%'` e agrupar

**Colunas retornadas (agregadas):**
```
ITEM | DESC | SUBGRUPO_FULL | ESTOQUE CONTÁBIL | ESTOQUE EXCEDENTE
VALOR DE INV EXCEDENTE | POPULARIDADE | CLASSIFICACAO DETALHADA
VENDAS_ANO_1 | VENDAS_ANO_2 | VENDAS_ANO_3
```

## Decisões de Design

| Questão | Decisão |
|---------|---------|
| Agrupamento do parquet | Agregar por `ITEM` antes do join (elimina duplicatas de CONTA) |
| Campo de busca subgrupo | Usar `SUBGRUPO_FULL` (já concatena COD + DESC) |
| Campo de busca grupo | Usar `GRUPO` |
| Fallback sem parquet | Continua com Eixo Vendas + mensagem de instrução |
| Filtro de TES | **Implementado** — usando lista centralizada em `src/config.py` |
