## 1. Objetivo

Transformar o Scanner em uma **ferramenta de investigação autossuficiente** que consolida em um único comando todas as informações necessárias para a análise de desempenho de um Produto, Subgrupo ou Grupo. O Scanner deve eliminar a necessidade de consultar múltiplos scripts ou planilhas separadas.

## 3. Correções Obrigatórias (Falhas Identificadas no Brainstorming)

### ❌ Falha 1 — Sem Filtro de TES (Alta Severidade)
**Problema:** O Scanner atual soma vendas brutas sem filtrar TES de devolução, bonificação e transferência interna. Os números exibidos podem estar incorretos.

**Solução:**
- Criar `src/config.py` com a lista centralizada de `TES_VENDAS_LIMPAS`
- O Scanner e o `extract_faturamento.py` devem importar essa constante
- **Dependência:** A definição dos códigos TES exatos deve ser feita na sessão dedicada ao Motor de Faturamento

### ❌ Falha 2 — Dessincronismo Temporal (Média Severidade)
**Problema:** O Eixo Vendas traz dados em tempo real do Fabric, enquanto o Eixo Estoque lê um cache local que pode estar desatualizado (dias ou semanas de diferença).

**Solução:**
- Ao carregar o parquet, ler o timestamp de geração do arquivo (`os.path.getmtime`)
- Exibir cabeçalho: `[ESTOQUE] Dados de: DD/MM/YYYY HH:MM — para atualizar: python src/enrich_inventory_data.py`
- Se o arquivo tiver mais de 7 dias, exibir **AVISO** de dados potencialmente desatualizados

### ❌ Falha 3 — Agregação Inconsistente por Subgrupo (Alta Severidade)
**Problema:** O parquet de estoque está no nível de SKU/ITEM. Quando o Scanner pesquisa `--type subgrupo`, ele não consegue agregar o estoque corretamente porque o campo de subgrupo pode ser diferente entre o Excel e o Fabric.

**Solução:**
- Validar no `enrich_inventory_data.py` que o campo `SUBGRUPO` tem o mesmo valor nos dois mundos (Fabric e Excel)
- No Scanner, ao buscar por subgrupo, aplicar `groupby('SUBGRUPO')` no parquet para somar `SALDO_ATUAL`, `VALOR_EXCESSO`
- Tratar nulos: itens sem subgrupo devem ser agrupados como `SUBGRUPO = 'N/A (sem cadastro)'`

### ❌ Falha 4 — Dependência de Parquet Não Documentada (Média Severidade)
**Problema:** Se o usuário rodar o Scanner sem ter executado o `enrich_inventory_data.py`, o script quebrará com erro genérico Python.

**Solução:**
```python
# Verificação de existência do cache (a implementar no Scanner)
PARQUET_PATH = Path("data/base_estoque_enriquecida.parquet")
if not PARQUET_PATH.exists():
    print("[AVISO] Cache de estoque não encontrado.")
    print("        Para ativar o Eixo Estoque, execute:")
    print("        python src/enrich_inventory_data.py")
    df_estoque = None  # Continua sem o eixo estoque
```

## 4. Decisões de Design

| Decisão | Escolha | Alternativa Descartada | Motivo |
|---------|---------|------------------------|--------|
| Filtros de TES | Constante em `src/config.py` | Hardcoded em cada script | Manutenção centralizada |
| Dados de Estoque | Parquet local (v2) | SQL direto no banco | Velocidade; banco é próximo passo |
| Fallback sem cache | Continua com aviso | Aborta o script | Usabilidade — Scanner ainda é útil sem estoque |
| Busca de Subgrupo | `LIKE` no Fabric + `groupby` no parquet | Join em memória | Simplicidade e robustez |
