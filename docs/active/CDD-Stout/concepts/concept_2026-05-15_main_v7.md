# 🔬 Prompt de Pesquisa Profunda: Insight Engineering para Executive Daily Reports

> **Objetivo:** Usar este prompt em uma ferramenta de pesquisa profunda (Deep Research, NotebookLM, Perplexity Pro, etc.) para fundamentar a criação profissional de insights de dados para um relatório diário executivo por e-mail.

---

## O PROMPT

```text
Preciso construir um sistema de "Daily Executive Intelligence Report" enviado por e-mail para um diretor de pós-venda de uma concessionária John Deere (máquinas de construção pesada). O relatório será 100% textual (Markdown renderizado em e-mail), sem dashboards ou links externos.

O público é um executivo que:
- Não tem tempo para ler mais de 3 minutos
- Precisa de números auditados e confiáveis
- Quer saber "o que mudou" e "o que fazer"
- Valoriza comparações (hoje vs ontem, semana vs semana)
- Desconfia de números que não batem com a realidade dele

Pesquise profundamente e me entregue um relatório estruturado cobrindo TODOS os tópicos abaixo:

---

### BLOCO 1: FRAMEWORKS DE INSIGHT PROFISSIONAL

1. **McKinsey SCQA Framework (Situation, Complication, Question, Answer):**
   - Como aplicar SCQA para transformar um dado bruto (ex: "faturamento caiu 22%") em uma narrativa executiva completa?
   - Exemplos reais de aplicação em relatórios de vendas B2B.

2. **Pyramid Principle (Barbara Minto):**
   - Como estruturar um insight usando a pirâmide invertida?
   - Quando usar "top-down" vs "bottom-up" para apresentar dados?

3. **"So What?" Test:**
   - Como aplicar o teste "E daí?" em cascata para garantir que todo insight tem implicação de negócio?
   - Quantas camadas de "So What?" são ideais para um relatório diário?

4. **Outros frameworks de Data Storytelling:**
   - Cole Nussbaumer Knaflic (Storytelling with Data)
   - Framework "Context → Insight → Action" 
   - "Assertion → Evidence → Impact" model

---

### BLOCO 2: ANATOMIA DO E-MAIL EXECUTIVO PERFEITO

1. **Estrutura ideal de um Daily Report por e-mail:**
   - Qual é a estrutura que CEOs e diretores mais engajam?
   - Quantas seções? Qual tamanho ideal?
   - O que vai no subject line para garantir abertura?

2. **Formatação em texto puro / Markdown:**
   - Best practices para usar tabelas, bullet points, emojis e blocos de citação em e-mails executivos
   - Como criar hierarquia visual sem HTML pesado
   - Uso de Unicode characters para simular gráficos em texto (spark lines, barras)

3. **Cadência e ritmo:**
   - Como variar o conteúdo ao longo da semana (Segunda = recap, Sexta = projeção)?
   - Como evitar "fadiga de relatório" (report fatigue)?
   - Estratégias de "Progressive Disclosure" — mostrar pouco no início e ir aprofundando conforme feedback

4. **Benchmarks de mercado:**
   - Como empresas como Morning Brew, The Hustle, CB Insights estruturam seus dailies?
   - O que a McKinsey e BCG recomendam para relatórios internos de vendas?

---

### BLOCO 3: ENGENHARIA DE INSIGHTS (DATA → STORY)

1. **Taxonomia de Insights:**
   - Quais são os tipos de insight (Anomalia, Tendência, Correlação, Benchmark, Previsão)?
   - Como classificar e priorizar insights para um executivo?
   - Existe um framework de "Insight Scoring" que eu possa adaptar?

2. **Embasamento estatístico para não-estatísticos:**
   - Como apresentar desvios padrão, percentis e z-scores de forma que um executivo entenda?
   - Quando usar "X é 3x maior que a média" vs "X está no top 5%"?
   - Como calcular e apresentar "anomalias" sem usar jargão técnico?

3. **Comparações que funcionam:**
   - Quais tipos de comparação geram mais impacto? (vs período anterior, vs meta, vs benchmark, vs concorrente)
   - Como apresentar "deltas" (variações) de forma clara?
   - O conceito de "anchor numbers" — dar um número de referência antes do número real

4. **Narrativa de causalidade:**
   - Como ir além de "o que aconteceu" para "por que aconteceu"?
   - Técnicas de "root cause narration" em relatórios de vendas
   - Como evitar correlações espúrias e ser honesto sobre incertezas

---

### BLOCO 4: AUDITORIA E CONFIANÇA NOS NÚMEROS

1. **Como construir confiança em dados novos:**
   - Estratégias para introduzir uma nova fonte de dados para um executivo cético
   - O conceito de "Trust Through Transparency" — mostrar a metodologia
   - Como lidar com discrepâncias entre os números do relatório e os números que o executivo "sente"

2. **Checksums visuais:**
   - Técnicas para incluir "provas de auditoria" inline no relatório
   - Ex: "Total confere com o Protheus: ✅" 
   - Como implementar um "Confidence Score" por seção

3. **Governança de dados em relatórios automatizados:**
   - Como versionar e rastrear a origem de cada número?
   - Práticas de "Data Lineage" simplificadas para relatórios

---

### BLOCO 5: CASOS DE USO EM PÓS-VENDA / HEAVY EQUIPMENT

1. **Métricas críticas de pós-venda de máquinas pesadas:**
   - Quais KPIs são padrão na indústria? (Parts Absorption Rate, SOW, First-Time Fix Rate, etc.)
   - Como reportar "Share of Wallet" de forma acionável?
   - Métricas de saúde de carteira (churn, frequência, ticket médio)

2. **Relatórios de referência no setor:**
   - Como a Caterpillar, Komatsu e Volvo CE reportam performance de pós-venda aos dealers?
   - Existe um padrão OEM para daily/weekly reports?

3. **Inteligência competitiva em peças:**
   - Como monitorar e reportar perda de market share para o mercado paralelo?
   - Indicadores de "vazamento" (clientes com máquina ativa mas sem compra de peças)

---

### FORMATO DE ENTREGA

Para cada bloco, me entregue:
1. **Resumo executivo** (3-5 bullets)
2. **Framework ou template aplicável** (que eu possa usar diretamente)
3. **Exemplos concretos** adaptados ao meu contexto (pós-venda John Deere, peças de construção)
4. **Fontes e referências** para aprofundamento

Priorize profundidade e aplicabilidade prática sobre generalidades.
