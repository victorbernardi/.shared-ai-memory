# Plano de Ajuste: Whitelist e Mapeamento de Consultores (Roberto's Team)

## Problema Identificado
Existe uma sobreposição de IDs no Protheus (`SA3010`). IDs como `000720` e `000730` estão atribuídos a múltiplos nomes (ex: Luana Ester vs Julio Cesar). O script `consolidate_bup.py` está capturando o primeiro nome encontrado no banco, o que resulta em "ruído" (Julio Cesar, Vitoria Eduarda, etc.) aparecendo no relatório final, mesmo quando a venda pertence ao time do Roberto.

## Objetivos
1.  Garantir que apenas os **14 nomes oficiais** do time do Roberto apareçam no relatório.
2.  Resolver a poluição de nomes causada pela sobreposição de IDs.
3.  Sincronizar a "Golden Copy" da whitelist em `segment_rules.json`.

## Mudanças Propostas

### 1. Governança (`data/config/segment_rules.json`)
*   Manter a White List de IDs (`vendedores_permitidos`).
*   Expandir a Black List de nomes (`vendedores_bloqueados_nomes`) para incluir todos os "ruídos" identificados: `JULIO CESAR DA CRUZ BARBOSA`, `VITORIA EDUARDA NOGUEIRA CARDOSO`, `THIAGO ROMUALDO MOREIRA`, `SIDNEI DE SOUZA`.

### 2. Motor de Consolidação (`scripts/consolidate_bup.py`)
*   **Prioridade de Mapeamento**: Modificar a criação do `mapa_vendedores` para que, se um ID estiver no `vendedores_ativos_2026.json`, o nome desse JSON seja utilizado, ignorando qualquer duplicata do `SA3010`.
*   **Filtro de Purga**: Aplicar a Black List de nomes na carga do `SA3010` para evitar que nomes indesejados entrem no dicionário de fallback.

### 3. Gerador de Configuração (`scripts/generate_active_sellers_config.py`)
*   Validar se o script está gerando o JSON corretamente (ele já possui a lógica de blacklist, mas precisa ser executado após o ajuste das regras).

## Verificação
1.  Executar `python scripts/generate_active_sellers_config.py` e validar o JSON resultante.
2.  Executar `python scripts/consolidate_bup.py`.
3.  Validar o Excel final: filtrar a coluna "Consultor" e garantir que apenas os 14 nomes oficiais apareçam.
